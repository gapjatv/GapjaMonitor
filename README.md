# 갑자TV 관제탑 — 안드로이드판

운빨존많겜 보스 감시를 폰에서 돌리는 앱입니다. PC판(`gapjatv_control_tower57.py`)의
인식 알고리즘과 80R 확정 로직을 그대로 옮겼습니다.

---

## ⚠️ 먼저 알아두실 것

**1. 빌드는 직접 하셔야 합니다.**
APK를 미리 만들어 드릴 수 없었습니다 (작업 환경에서 Android SDK 다운로드가 막혀 있었습니다).
Android Studio에서 열고 빌드 버튼만 누르면 됩니다. 아래 순서대로 하면 10분이면 끝납니다.

**2. 안드로이드 OS 제약 — 피할 수 없는 것들**

| 제약 | 설명 |
|---|---|
| 캡처 동의 창 | 앱을 켤 때마다 "화면 녹화를 시작할까요?" 동의가 필요합니다. OS 규칙이라 생략 불가 |
| 상태바 표시 | '화면 공유 중' 칩이 계속 남습니다. 숨길 수 없습니다 |
| 화면 잠김 | 화면이 꺼지면 캡처가 자동 중단됩니다. 게임 중에는 문제되지 않습니다 |
| 성능 | 게임도 같은 폰에서 돌아갑니다. 버벅이면 '화면 축소'를 낮추고 '검사 간격'을 늘리세요 |

**3. OBS는 없습니다.**
PC판의 순차 세로·중앙·투명 크로마키 창은 OBS에 넣기 위한 것이었습니다. 폰에는 OBS가
없으니, 대신 **게임 화면 위에 떠 있는 오버레이 패널**이 그 역할을 합니다.

**4. iOS는 만들 수 없습니다.**
다른 앱 화면을 백그라운드로 계속 읽을 방법이 iOS에는 없습니다 (ReplayKit은 매번 사용자가
직접 시작해야 하고 메모리 50MB 제한). 폰에서 쓰시려면 안드로이드만 가능합니다.

## 빌드 방법

### ① Android Studio로 빌드 (권장)

1. [Android Studio](https://developer.android.com/studio) 설치 (무료)
2. `File → Open` → 이 폴더(`GapjaMonitor`) 선택
3. 처음 열면 Gradle이 필요한 것들을 자동으로 받습니다 (5~10분, 인터넷 필요)
4. 폰을 USB로 연결하고 **개발자 옵션 → USB 디버깅**을 켭니다
5. 상단의 ▶ 실행 버튼

APK 파일만 뽑으려면 `Build → Build Bundle(s)/APK(s) → Build APK(s)`.
결과는 `app/build/outputs/apk/debug/app-debug.apk` 에 생깁니다.

### ② OpenCV를 직접 넣는 방법 (①에서 오류가 날 때만)

`app/build.gradle.kts` 의 `org.opencv:opencv:4.10.0` 을 찾지 못한다는 오류가 나면:

1. [OpenCV 안드로이드 SDK](https://opencv.org/releases/)를 내려받아 압축을 풉니다
2. `File → New → Import Module` → 압축 푼 폴더의 `sdk` 선택
3. `app/build.gradle.kts` 에서 그 줄을 지우고 `implementation(project(":opencv"))` 로 바꿉니다

## 처음 설정 (앱 실행 후)

### 1. 보스 스크린샷 등록 — **필수**

PC에서 쓰던 PNG를 그대로 쓰면 됩니다. 파일 이름이 보스 이름과 같아야 합니다.

```
그런트.png
거대 전기로봇.png
악마 모노폴리.png
...
```

폰으로 옮기는 방법: USB 연결 후 폰의 다운로드 폴더에 복사 → 앱에서 `🖼 PNG 등록` → 전체 선택.

**보조 스샷** — 네임텍이 겹친 화면을 따로 찍어 `그런트_2.png` 처럼 넣어두면
가려졌을 때 특히 잘 잡힙니다. `_2` `_3` `_4` 까지 쓸 수 있고, 없어도 상관없습니다.

### 2. 오버레이 권한

`🔓 오버레이 권한 허용` → 설정에서 '다른 앱 위에 표시' 켜기.
이게 없으면 게임 위에 보스 패널이 안 뜹니다.

### 3. 음성 (선택)

PC에서 쓰던 `voices/*.mp3` 를 넣으면 **같은 목소리**로 나옵니다.
없으면 폰 내장 TTS가 읽습니다. 폰에서는 애저·엣지 TTS가 필요 없습니다 —
내장 TTS가 네트워크 없이 즉시 나오고, PC판에서 고생했던 403 문제가 없습니다.

### 4. PC 기록 가져오기 (선택)

`boss_sequences.json` 파일 형식이 PC판과 **완전히 같습니다.**
`📥 PC 기록 가져오기` 로 PC에 쌓인 판별 기록을 이어서 쓸 수 있고,
`📤 내보내기` 로 폰 기록을 PC로 보낼 수도 있습니다.

## 쓰는 법

1. 모드를 **침공** 또는 **태초** 로 맞춥니다
2. `▶ 시작` → 캡처 동의
3. 게임으로 돌아가 플레이합니다. 보스가 보이면 자동으로 인식됩니다
4. 판이 끝나면 `🔄 판 종료·기록` — 이번 판의 보스 순서가 저장됩니다
5. `📊 판별 기록 분석` 으로 쌓인 통계를 봅니다

잘못 인식됐을 때는 `↩️ 되돌리기` (알림창에서도 누를 수 있습니다).
되돌린 보스는 5초 동안 다시 인식하지 않습니다.

## 들어 있는 기능

**인식**
- 멀티스케일 템플릿 매칭 (8단계) + 조기 종료·조기 중단
- 근접 구간 구제: 보충 크기 → 보조 스샷 → 타일 분할 투표
- 네임텍 가려짐 구제 (4×4 = 16조각, 기하 일치 투표, 윤곽선 검증)
- PSR·윤곽선·연속프레임 검사 (깐깐 검사 대상에만)

**80라운드**
- 침공특수보스 2종이 인식되면 남은 1종을 **100% 확정** (확률이 아니라 소거법)
- 그런트·양술사 인식 여부에 따른 조건별 안내 멘트 5종
- 확정 순간의 조건을 붙잡아 두므로, 안내 지연 중에 상황이 바뀌어도 멘트가 흔들리지 않습니다
- 판당 정확히 1회만 안내

**판별 기록 분석**
- 침공특수보스 순서 비율 (30R/50R/80R 각각 몇 번)
- 전체 등장 순서 조합 6가지 + 카이제곱 검정
- 메인보스 순서 반복 여부 — 기준 길이가 기록량에 따라 자동으로 올라가고,
  푸아송 검정으로 "우연보다 유의하게 많은가"를 판정합니다
- 인식 누락 경고 (특정 특수보스가 기대보다 25% 이상 적게 잡히면 알려줍니다)
- CSV 내보내기

**오버레이**
- 인식된 보스를 순서대로 표시, 침공특수보스는 빨간 표시
- 80R 확정 / 80R 예상 강조
- 손가락으로 끌어 위치 조절, 위치 저장

## 폴더 구조

```
GapjaMonitor/
├─ app/src/main/java/tv/gapja/monitor/
│  ├─ core/                   ← 화면·OpenCV와 무관한 순수 로직 (테스트 완료)
│  │  ├─ BossCatalog.kt       보스 목록, 기준값, 타일 구제 상수
│  │  ├─ Matcher.kt           매칭 알고리즘 (멀티스케일·타일투표·윤곽선)
│  │  ├─ Predictor.kt         80R 소거법, 조건별 멘트
│  │  ├─ SeqStore.kt          판별 기록, 순서 비율, 패턴 검정
│  │  ├─ SeqJson.kt           PC와 호환되는 JSON 읽기
│  │  └─ GameSession.kt       한 판의 진행 상태
│  ├─ CaptureService.kt       화면 캡처 + 감시 루프
│  ├─ CvOps.kt                OpenCV 구현체
│  ├─ OverlayService.kt       게임 위 패널 (OBS 크로마키 대체)
│  ├─ Speaker.kt              MP3 + 내장 TTS
│  ├─ TemplateStore.kt        보스 PNG 관리
│  ├─ SeqRepo.kt              기록 파일 읽기/쓰기/내보내기
│  ├─ Prefs.kt                설정값
│  ├─ Bus.kt                  서비스 ↔ 화면 전달
│  ├─ MainActivity.kt         메인 화면
│  └─ AnalysisActivity.kt     📊 분석 화면
└─ app/build.gradle.kts
```

`core/` 폴더는 안드로이드·OpenCV에 의존하지 않습니다. 그래서 알고리즘만 따로 컴파일해
테스트할 수 있고, 실제로 그렇게 검증했습니다 (아래).

## 검증한 것 / 못한 것

**검증했습니다** — `core/` 를 Kotlin 2.4.21로 컴파일해 단위 테스트를 돌렸습니다.

- 멀티스케일 매칭: 6종 전부 정확한 좌표에서 인식
- 네임텍 가려짐: 위/중간/아래 × 25·40·50% = 54건 **전부 구제** (원점 오차 0.0px)
- 오인식: 가짜 30건 중 조각투표 통과 0건
- 윤곽선 검증이 '색만 비슷한 다른 보스' 전부 차단
- 80R 소거법 6가지 조합 전부 정확, 판당 1회만 확정
- 조건별 멘트 11가지 경우 전부 정확 (조건 1~4)
- 확정 시점 조건 붙잡기 (지연 중 상황이 바뀌어도 멘트 유지)
- 되돌리기 + 쿨다운, 타일투표 쿨다운
- PC JSON 읽기/쓰기 왕복, 깨진 파일 7가지에서 예외 없음
- 우연 일치 기대 횟수가 PC판 실측표와 일치 (50/300/1000판 × 4~7칸)
- 진짜 패턴 검출 60/60, 무작위 오탐 0%

**못 했습니다** — Android SDK를 받을 수 없어 `CaptureService` 등 OS에 닿는 파일은
컴파일 검증을 하지 못했습니다. 처음 빌드할 때 오류가 나면 그 메시지를 그대로
알려주시면 바로 고쳐 드립니다.

## 성능 조절

폰이 게임과 인식을 동시에 돌리므로 조절이 필요할 수 있습니다.

| 증상 | 조치 |
|---|---|
| 게임이 버벅인다 | 화면 축소를 40% → 30%, 검사 간격을 150ms → 300ms |
| 보스를 늦게 잡는다 | 검사 간격을 100ms로 줄임 |
| 작은 보스를 놓친다 | 화면 축소를 60~70%로 올림 |
| 엉뚱한 곳을 보스로 잡는다 | 그 보스의 기준값을 올림, 또는 조각 동의 수를 10~12로 올림 |
| 가려져도 잘 안 잡힌다 | 조각 동의 수를 6~7로 낮춤 (오인식 위험은 조금 올라갑니다) |

## PC판과 다른 점

| | PC판 | 안드로이드판 |
|---|---|---|
| 감시 대상 | MuMu Player 창 | 폰 화면 전체 |
| 보스 표시 | OBS 크로마키 창 3종 | 게임 위 오버레이 패널 |
| 음성 | 애저/엣지/구글/윈도우 4단 폴백 | MP3 → 내장 TTS 2단 |
| 깐깐 검사 | 거대 전기로봇 포함 | 기본 비활성 (아래 설명) |
| BGM·채팅봇 | 있음 | 없음 (방송 기능은 PC에서) |

**깐깐 검사를 기본으로 끈 이유**: PC 통계 446판을 분석했을 때 거대 전기로봇이
다른 침공특수보스보다 **약 39% 적게 인식**되고 있었습니다 (카이제곱 47.5, p≈5×10⁻¹¹).
PSR·윤곽선·연속프레임 3관문이 가려짐에 취약한 탓으로 보여, 폰판에서는 비워 뒀습니다.
오인식이 생기면 `BossCatalog.STRICT_BOSSES` 에 이름을 넣으면 됩니다.
